## Key architectural decisions made during Day 1 debugging

| Decision | Rationale |
|---|---|
| **Vertex AI over AI Studio API key** | AI Studio free tier has 5–10 RPM and a `limit: 0` for Pro models. Vertex AI accepts GCP credits and has higher quotas. Auth via Application Default Credentials (`gcloud auth application-default login`). |
| **Deterministic pipeline (intent→discovery→ranking→booking→followup) instead of LLM-orchestrated dispatch** | The LLM-driven orchestrator was making 2× the API calls (one per step decision) which inflated latency from ~50s to >180s. Pipeline order isn't a business decision — it's an architectural choice — so it lives in code. **All business reasoning (rank, pick, schedule) still happens in agent prompts.** |
| **Firestore opt-in via `USE_FIRESTORE=true`** | Just setting `GCP_PROJECT` (for Vertex AI) was accidentally turning on Firestore writes, which crashed with `5 NOT_FOUND` on un-initialized collections. Separating the flags makes Vertex AI usable without Firestore. |
| **Firestore writes fail-soft** | Pipeline crash from a persistence error is unacceptable. All Firestore writes are now wrapped in try/catch and use `set({ merge: true })` instead of `update()` so missing docs don't 404. |
| **Compact state per agent** | Each subagent only sees the prior pipeline outputs it needs (e.g., booking gets `recommendation` not the full ranking blob). Shrinks prompt size, cuts token cost and latency. |
| **`res.on('close')` for client-disconnect, not `req.on('close')`** | The latter fires when Express body-parser finishes reading — a Node footgun. We were aborting the pipeline immediately after parsing the request body because of this misfire. |
| **MAX_TOOL_ROUNDS=4 with coercion fallback** | Some models (especially flash-lite) call tools but don't emit final JSON. Coercion sends one more no-tools call to force structured output. |

## Bugs found and fixed (not in any particular order)

1. **`req.on('close')` misfire** — caused immediate "client disconnected" abort
2. **GCP_PROJECT enables Firestore** — caused `5 NOT_FOUND` on every trace write
3. **Free-tier `gemini-2.5-pro` has `limit: 0`** — pivoted to Vertex AI
4. **flash-lite weak at structured-output-after-tools** — added coercion fallback
5. **dotenv not auto-loaded** — added `import 'dotenv/config'` to `index.ts`
6. **Async generator yield not visible to caller** — diagnosed via per-iteration logs, ruled out
7. **Per-step orchestrator LLM call doubled Gemini load** — replaced with deterministic dispatch
8. **State JSON containing full taxonomy entries** — slimmed via `compactState()`
9. **`update()` on non-existent doc returns 5 NOT_FOUND** — use `set({merge:true})`
10. **Server-Sent Events buffering** — confirmed working with `/ping-sse`; not a Node/Express issue

## What runs at runtime — confirmed

- **Backend**: Express on Node 25, port 8080
- **LLM**: Gemini 2.5 Flash via Vertex AI (`@google/genai` v1 with `vertexai: true`)
- **Auth**: GCP Application Default Credentials (no Antigravity dependency)
- **Storage**: In-memory `Map<>` (Firestore opt-in)
- **Agent code**: TypeScript ReAct loop in `gemini.ts`, deterministic pipeline in `orchestrator.ts`
