## Bugs found and fixed during Day 3

1. **`/healthz` was intercepted by Cloud Run frontend** — Google's GFE returned its own 404 for that exact path. Fix: rename to `/status` (also kept `/healthz` and `/` as aliases for compatibility).

2. **`/ping-gemini` diagnostic endpoint used API-key mode** — but we deployed with `USE_VERTEX_AI=true` and no API key set. Fix: branch on `config.gemini.useVertex` to construct the client correctly.

3. **Cloud Build .gcloudignore was too loose initially** — it would have shipped node_modules. Tightened to exclude `**/node_modules`, `mobile/`, `recordings/`, `flutter_sdk.zip`, `*.apk`.

4. **Default compute SA needed IAM grant** for `roles/aiplatform.user`. Script grants it automatically (idempotent).

## Architecture decisions made today

| Decision | Why |
|---|---|
| Single Dockerfile at repo root (not nested in backend/) | Need to copy both `backend/` AND `data/` into the container; cleanest with repo-root context. |
| Use `tsx` in production (not `tsc` + `node`) | Avoids a compile step and `.js` import-path conversion. Slight startup cost (<100ms). |
| `USE_FIRESTORE=false` in Cloud Run env | In-memory store still works on Cloud Run (single-instance traffic). Firestore is a Day 4+ optimization for multi-instance. |
| `containerConcurrency: 10`, `maxScale: 10`, `memory: 1Gi` | Agent calls take 30-60s; 10 concurrent runs per instance is a sane default. |
| Allow unauthenticated access | Demo / hackathon submission needs to be accessible by judges without auth. Real product would add Firebase Auth in Phase 1. |
| GitHub Release with APK attached (not Firebase App Distribution) | App Distribution requires Firebase project setup + email allowlist for testers. GitHub Release link works for any judge with the URL. |
